# Paper Fold effect

Paper Fold is Capinsta's original fold/unfold animation effect for video, images, text, captions, stickers, and graphics. It uses paired paper and matte animation frames to reveal source pixels while compositing a paper surface around the fold.

The implementation is clean-room. It does not load, invoke, copy, or redistribute the FoldCraft plug-in, its binary, branding, presets, license system, or embedded artwork. The four bundled development styles are generated by Capinsta code and carry an explicit replacement notice.

## User-facing behavior

Add **Paper Fold** from **Effects → Animation & Stylize** after selecting a compatible layer. The effect is clip-local, deterministic while scrubbing, and included in the normal project effect array. It therefore participates in save/load, undo/redo, duplicate, clipboard, keyframing, thumbnail rendering, preview, and export through the existing editor systems.

### Animation

- **Mode** selects Fold In, Fold Out, Fold In and Out, or Manual.
- **Progress** controls normalized open progress in Manual mode. `0` is folded and `1` is open.
- **In Duration** and **Out Duration** are seconds. If a clip is too short, both transitions are scaled proportionally.
- **Hold Duration** reserves an open interval between in and out transitions.
- **Reverse** swaps open and folded progress.
- **Frame Hold** holds each timing frame for an integer number of timeline frames.
- **Posterize FPS** quantizes animation time. `0` uses timeline FPS.
- **Animation Offset** shifts clip-local effect time in seconds and may be negative.
- **Random Seed** controls deterministic shake and generated detail.

### Fold style

- **Fold Style** selects Center Fold, Corner Fold, Envelope Fold, or Crumple Fold.
- **Fold Direction** and **Fold Origin** orient the generated paper and matte frames.
- **Fold Intensity** scales matte contribution.
- **Paper Scale**, **Paper Rotation**, and **Paper Position X/Y** transform the paper independently.
- **Flip Horizontal/Vertical** mirror the finished effect.

### Media and alpha

- **Media Scale**, **Media Rotation**, and **Media Position X/Y** transform source pixels before matte clipping.
- **Media Opacity** controls source contribution.
- **Fit Mode** supports Contain, Cover, and Stretch in the Canvas2D fallback. Native-size GPU preprocessing has the same aspect ratio as its source, so the modes converge there.
- **Alpha Mode** supports Source Alpha, Luma, and Green Screen.
- **Key Color**, **Key Similarity**, **Key Smoothness**, and **Spill Suppression** configure chroma keying.
- **Alpha Threshold** and **Alpha Feather** reshape the resulting alpha.

### Appearance, border, shadow, and transform

Paper color/tint, generated texture, opacity, exposure, contrast, saturation, deterministic noise, and halftone controls apply to the paper layer. Border and shadow have independent enable, color, width/opacity, blur, distance, and angle controls. The final position, scale, rotation, seeded shake, opacity, and original mix apply to the assembled result.

## Timing model

Timing and manifest validation live in `rust/crates/paper-fold`; the web renderer calls the same functions through `opencut-wasm`.

Input time is the visual node's clip-local timeline time. Trimming and source retiming affect decoded source time but do not change the Paper Fold animation clock. Frozen source frames can therefore continue folding. Preview and export both pass exact frame timestamps to the same resolver.

The resolver:

1. Adds animation offset.
2. Quantizes to Posterize FPS.
3. Applies Frame Hold in timeline-frame space.
4. Resolves the selected animation mode.
5. Applies Reverse.
6. Clamps and selects a manifest frame.
7. Generates shake from seed, held time, frequency, and channel using an integer hash.

Rendering never calls `Math.random()`.

## Rendering pipeline

### Preview

Scene resolution produces decoded/rasterized source nodes and a `PaperFoldRuntimeState`. Frame descriptor construction then chooses the GPU path when the generated atlas is valid:

1. Upload the source texture.
2. Reuse or upload one cached paper/matte atlas.
3. Run the Paper Fold source pass at native source dimensions.
4. Apply the regular layer transform.
5. Run ordinary Capinsta effect groups.
6. Apply masks and blend into the scene.

Paper Fold is a source pass because applying it after the layer transform would make its atlas cover the entire composition instead of the layer.

Text is rasterized to its persistent texture first, then follows the same source-pass path. Capinsta captions retain their React DOM renderer; the overlay derives the same timing state and applies the fold wrapper in both interactive preview and the headless export page.

Preview proxy behavior comes from the existing scene builder and decoded-source caches. Paper Fold processes the proxy dimensions it receives and reuses the same atlas and shader program.

### Export

`SceneExporter` uses the same `CanvasRenderer`, render tree, frame descriptor builder, source passes, WASM compositor, and timing resolver used by preview. Export constructs the renderer at requested output size and advances it using export frame timestamps, so a differing export FPS changes sampling frequency but not the effect's time function.

Capinsta's headless export page uses the same React caption overlay component as preview. The fallback ForeignObject caption exporter remains an existing repository limitation unrelated to Paper Fold.

### Fallbacks

The intended order is:

1. GPU source pass with the paired atlas.
2. Canvas2D pre-rasterizer when atlas preparation or validation fails.
3. Original source when Canvas2D processing also fails.

Warnings are keyed by effect ID and emitted once to prevent console flooding. Canvas2D uses `OffscreenCanvas` when available and an HTML canvas fallback on the main thread. It never mutates a decoded frame or shared source canvas.

WebGPU context loss is still governed by Capinsta's compositor lifecycle. The effect does not read pixels back from the GPU.

## Fold asset format

Each style has a stable manifest:

```ts
interface PaperFoldStyleManifest {
	id: "center-fold" | "corner-fold" | "envelope-fold" | "crumple-fold";
	name: string;
	version: number;
	width: number;
	height: number;
	frameCount: number;
	frames: Array<{ paper: string; matte: string }>;
	defaultDirection?: "left" | "right" | "up" | "down";
	supportsReverse: boolean;
	assetKind: "generated-placeholder";
	replacementNotice: string;
}
```

Paper frames are transparent RGBA. Matte frames use white/alpha for visible media and transparent/black for folded media. The atlas stores paper cells in its left half and corresponding matte cells in its right half with a shared grid.

Validation checks ID, dimensions, frame count, missing paper/matte references, and packed atlas size. The current 12-frame, 512×512 styles pack to a 4096×1536 atlas.

## Adding a fold style

1. Produce original or properly licensed paper and matte frames at one consistent size. Do not derive them from proprietary plug-ins.
2. Add a stable lowercase style ID and display name to the style registry in `apps/web/src/effects/paper-fold/assets.ts`.
3. Add the ID to `PaperFoldStyleId` and the Fold Style control options.
4. Supply one paper and one matte reference per frame. If replacing generated placeholders, implement an asynchronous loader that decodes each URL once to `ImageBitmap`.
5. Run manifest validation for a conservative 4096-pixel texture limit. Split larger styles across atlases before enabling them.
6. Verify progress snapshots at 0, 0.25, 0.5, 0.75, and 1 in Canvas2D and GPU paths.
7. Increment the style version when frame ordering or artwork changes so runtime caches invalidate.

Production artwork should preserve transparent edges, avoid color in matte RGB channels that changes grayscale sampling, and be authored for premultiplied-alpha-safe compositing.

## Performance strategy

- Generated frames, atlases, compositor textures, shader pipelines, and raster scratch surfaces are cached.
- Scratch surfaces use a bounded LRU and are reused by effect ID and dimensions.
- The WASM compositor releases uploaded atlases when they disappear from subsequent frame descriptors.
- Canvas allocation, asset generation, and shader creation are outside the normal per-frame hot path.
- Chroma/luma CPU pixel processing occurs only in Canvas2D fallback.
- Active playback inherits proxy-size sources; paused/full export inherits the renderer's higher resolution.
- No GPU readback occurs during normal rendering.

## Browser compatibility

The primary editor compositor requires the repository's supported WebGPU/WASM environment. Paper Fold's CPU renderer works with `OffscreenCanvas` or main-thread HTML canvas. Canvas filters, shadows, and composite modes may differ slightly across browser engines. Atlas dimensions must not exceed the device texture limit; validation falls back before upload when the configured limit is exceeded.

## Project data and migration

Project version 35 normalizes Paper Fold instances to schema version 1 and fills missing fields without replacing stored values. JSON contains only effect ID, type, enabled state, stable style ID, schema version, and parameter primitives. Canvases, decoded images, atlases, and runtime state are never serialized.

The existing generic effect commands provide add/remove/toggle/reorder/parameter undo, and the existing element duplicate/clipboard paths carry Paper Fold data without a custom side channel.

## Testing

Rust unit tests cover Fold In, Fold Out, Fold In and Out, Manual, Reverse, frame hold, posterization, frame selection, short/zero clips, seeded shake, negative offsets, and manifest/atlas validation.

Bun tests cover defaults, partial schema normalization, timing modes, frame clamping, clip-local trim/speed semantics, preview/export timestamp identity, missing manifest assets, GPU pass construction, JSON serialization, and project migration.

Browser validation should additionally cover:

- Apply, toggle, reorder, remove, undo, redo, duplicate, copy, paste, save, and reopen.
- Video, image, text, caption, sticker, and graphic sources.
- Forward/backward scrubbing and frozen/retimed video.
- Proxy playback and paused/full-resolution preview.
- Export at project FPS and a different FPS.
- Forced atlas failure and forced Canvas2D failure.
- WebGPU context loss and recovery.
- Snapshot frames at progress 0, 0.25, 0.5, 0.75, and 1 for every style.

## Troubleshooting

- **The original source is shown:** inspect the single structured `[paper-fold]` warning. Confirm the style manifest and Canvas2D availability.
- **Atlas upload fails:** reduce frame dimensions/count or split the style below the device texture limit.
- **Green spill remains:** increase Spill Suppression, then tune Similarity and Smoothness.
- **The fold jumps while scrubbing:** confirm caller time is clip-local and all renderers use the Rust timing resolver.
- **A saved project has missing controls:** confirm it reached project version 35 and that the effect's `schemaVersion` is 1.
- **Caption and media folds look slightly different:** captions use the shared DOM overlay to preserve preview/export identity, while media uses the authored/procedural paired-atlas compositor.
